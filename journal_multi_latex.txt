\chapter{Visão Geral do Sistema}

\section{Objetivo}
O \texttt{journal\_strip\_multi\_chargers.py} é uma ferramenta de engenharia avançada projetada para realizar a coleta massiva e análise de logs em infraestruturas de carregamento de veículos elétricos (EV). O foco principal é extrair payloads hexadecimais do serviço \texttt{chargepoint.service}, permitindo a reconstrução de sessões de carregamento nos protocolos \textbf{CHAdeMO} e \textbf{CCS}.

\section{Arquitetura de Software}
O script utiliza o paradigma de \textbf{Programação Assíncrona} através da biblioteca \texttt{asyncio}. Diferente de modelos multi-thread tradicionais que consomem muita memória, este modelo permite gerenciar centenas de conexões SSH simultâneas em um único loop de eventos, aguardando I/O sem bloquear o processamento principal.

\chapter{Estruturas de Dados e Classes}

\section{Dataclasses de Estado}
O código utiliza \texttt{dataclasses} para garantir imutabilidade e tipagem forte:

\begin{itemize}
    \item \textbf{\texttt{Charger}}: Armazena a identidade do hardware (\texttt{custom\_id} e \texttt{ip}).
    \item \textbf{\texttt{JournalReadStats}}: Contador volátil para monitoramento de linhas brutas vs. linhas filtradas.
    \item \textbf{\texttt{ChargerEvent}}: Objeto de transporte que notifica a interface sobre mudanças de estado (ex: "conectando", "salvando").
    \item \textbf{\texttt{ProcessResult}}: Resumo final da operação de um carregador individual.
\end{itemize}

\section{Gerenciamento de Logs (\texttt{EventLogger})}
A classe \texttt{EventLogger} é responsável pela persistência do histórico da aplicação. 
\begin{itemize}
    \item \textbf{Método \texttt{write}}: Adiciona timestamps e formata mensagens.
    \item \textbf{Segurança}: Utiliza \texttt{flush()} imediato para garantir que em caso de crash do script, os logs até aquele ponto não sejam perdidos no buffer do SO.
\end{itemize}

\section{O Hub de Eventos (\texttt{EventHub})}
Atua como um \textit{Broker} de mensagens interno. Quando uma corrotina de processamento de carregador detecta um progresso, ela emite um \texttt{ChargerEvent} para o Hub. O Hub então distribui essa informação para três destinos:
\begin{enumerate}
    \item O arquivo de log físico (via \texttt{EventLogger}).
    \item O console padrão (Stdout), se o modo silencioso estiver desligado.
    \item A fila assíncrona da interface \textit{Textual}, se a TUI estiver ativa.
\end{enumerate}

\chapter{Lógica de Processamento e Protocolos}

\section{Filtragem de Dados (Regex)}
O script busca o padrão \texttt{04 64 <byte>}. Este padrão é específico para as tramas de comunicação serial capturadas no journal do sistema Linux do carregador.
A expressão regular \texttt{re.compile(r"04 64 (?!10|11|e1)[0-9a-f]\{2\}.*")} exclui explicitamente bytes de controle não desejados (\texttt{10, 11, e1}).

\section{Detecção de Sessões}

\chapter{Manual de Métodos Principais}

\section{\texttt{load\_chargers(path)}}
Lê o arquivo DSV. Realiza a limpeza de aspas e espaços. Crucialmente, invoca \texttt{validate\_unique\_custom\_ids} para evitar que dois carregadores tentem escrever no mesmo arquivo de saída, o que causaria corrupção de dados.

\section{\texttt{run\_remote\_journal(...)}}
Este é o núcleo da comunicação. 
\begin{itemize}
    \item Abre a conexão SSH.
    \item Cria um processo remoto executando \texttt{journalctl}.
    \item Usa um gerador assíncrono para ler linha a linha (\texttt{async for raw\_line in process.stdout}).
    \item Atualiza estatísticas em tempo real para a TUI através do Hub.
\end{itemize}

\section{\texttt{save\_file(...)}}
Garante que os nomes dos arquivos sejam seguros para o sistema de arquivos utilizando a função \texttt{safe\_filename\_part}, que remove caracteres especiais e normaliza acentos para ASCII.
